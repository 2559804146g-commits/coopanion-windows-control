# Coopanion Windows Control

给同一个桌面伙伴接上真实的 Windows 应用：理解目标、执行步骤、读取实际结果，暂停后继续。聊天、声音、应用授权与活动记录放在 **Coopanion 原来的一个管理窗口** 里。原桌宠继续待在桌面，控制服务在后台运行。

这是基于 [Coopanion](https://github.com/Pal-AI-Lab/Coopanion) 的实验性扩展，非官方发行版。目前固定适配 **Windows 10/11、Coopanion 0.2.19 便携版**；其他版本未验证，安装器会拒绝直接套用。源码按 AGPL-3.0-or-later 发布，保留第三方各自许可。

## 能做什么

- 按应用分别选择“不允许 / 可打开 / 可观察 / 可操作”，随时撤销。
- 读取支持 Windows 辅助功能接口的应用控件，向普通单行输入框填写，点击普通按钮。每次操作绑定真实窗口、进程与短期控件快照。
- 网易云音乐桌面版的播放、暂停、切歌、搜索和指定版本选歌；实际核对播放器结果。
- 持续任务保存步骤、实际回执与暂停位置；用户正在操作时让行。不确定的动作先只读核对，不自动重放。
- 同一个原桌宠表现观察、打字、尾巴点击、等待和完成；动画跟随实际操作，不代替结果。
- 原管理页“桌面生态扩展 → 应用与活动”管理授权、音乐、桌面窗口、记录和任务。“生态与声音”管理朗读、音色和自主活动。
- 可选的语音模型、素材库和短唱模块与同一角色共用。使用者自行配置服务、配额和模型，源码包没有声音模型或歌曲。

不是所有应用都能操作：只有启动器的应用可能只能打开；自绘界面不一定暴露可用控件。普通控件适配拒绝受保护输入，以及发送、删除、付款、下载、账号设置等敏感操作。不会授予模型任意终端命令或文件系统访问。

## 直接安装（推荐）

从 [Releases](https://github.com/2559804146g-commits/coopanion-windows-control/releases) 下载 `CompanionControl-0.14.1-win-x64-Setup.exe`。安装完打开桌面快捷方式，在同一个管理窗口填写自己的聊天模型账号，再选择应用权限。无需安装 Node、执行命令或手动注册扩展。

整合包已包含原程序、控制扩展、中文离线朗读和 Whisper 语音识别环境。默认提供 Coo；原鲸鱼贴图与个人翻唱音色不随包再分发。数据保存在用户目录，升级与卸载默认保留。安装包尚未做代码签名，Windows 可能显示未知发布者。离线指语音与控制运行环境，聊天模型仍需要使用者自己的服务账号或另行配置本机模型。

## 从源码安装（开发者）

1. 安装 [Node.js 22 或更新的受支持版本](https://nodejs.org/)，从 [Coopanion 官方发行页](https://github.com/Pal-AI-Lab/Coopanion/releases/tag/v0.2.19)取得 **0.2.19 Windows 便携版**并解压。先在原版中完成自己的模型配置，确认能聊天。
2. 下载本仓库源码并解压到固定目录。双击 `安装.cmd`，输入包含 `Coopanion.exe` 的文件夹路径。第一次会安装 Electron 和页面构建依赖，需要联网。
3. 安装完成后，从 Coopanion 托盘进入原管理页的“World 扩展”，启用 / 添加 **Windows 桌面生态**，重启运行。扩展默认 `enabled=false`，不替你开启账号或授权应用。
4. 进入“桌面生态扩展 → 应用与活动”，选择你允许她使用的应用。网易云先设为“可操作”，再点“设为播放器”。之后直接和她说你要做什么。

命令行等价步骤（在本仓库目录）：

```powershell
npm ci
npm --prefix control-ui ci
npm run build:voice
node scripts/setup.mjs --companion "D:/Apps/Coopanion-0.2.19"
```

`--check` 只检查版本和必需文件，不修改原程序：

```powershell
node scripts/setup.mjs --companion "D:/Apps/Coopanion-0.2.19" --check
```

日常双击 `启动.cmd`、用原桌宠的设置入口，或按 `Ctrl+Alt+D`，打开的都是同一个原管理窗口。`Ctrl+Alt+P` 显示 / 隐藏原桌宠；语音说话键沿用原版自己的设置。关闭管理窗口后仍在后台运行；完全退出请用 Coopanion 原托盘退出。

## 数据与迁移

`config/runtime.json` 只记录你自己的 Coopanion 路径。扩展的计划、权限、记录、声音账号与作品在 `data/`；原版的人格和会话仍由原版保存。仓库不含任何用户账号、密钥、聊天、授权清单、缓存、音频或运行时。不要把这些目录追加到 Git。

模型密钥只在原版配置，语音服务账号在扩展“语音模型配置”中填写；QQ 是可选接入，使用自己的账号。没有预置免费共享额度。语音页的音色管理可勾选常用音色，下拉框只显示保存的常用清单和当前音色。

本地离线朗读需要另行安装相应语音模型；未安装时不要把下拉框里出现的名称当成已经可以发声。翻唱需自行配置 Python、FFmpeg、分离及 RVC 模型；没有配置会显示未就绪。首次推理可能很慢，已保存的同版本作品可直接复用。音色、歌曲与模型权利独立，不随源代码许可授予。

## 开发与检查

```powershell
npm test
```

测试数据使用隔离的临时目录，不会向 QQ 发消息。部分音频处理测试需要 FFmpeg，请通过 `FFMPEG_PATH` 指定其可执行文件。不要为跑测试复制真实密钥或用户数据。UI 构建源在 `control-ui/src`，构建产物在忽略的 `bridge/control-ui`。

主要模块：`native.mjs` / `app-control.mjs` 是真实 Windows 控制；`capabilities.mjs` / `tasks.mjs` 是能力和持续执行；`bridge/` 接入同一原核心及原界面；`integration/` 扩展原身体；`main.cjs` 只承载后台服务，不创建另一套主窗口。

## 更新、回退与边界

安装器只对固定版本做有限补丁，先校验所有目标，再写入；原文件与哈希保存到本机 `integration-backups/`。遇到未知版本或其他修改会停止覆盖。升级原版前先重新核对兼容性，不能直接复用旧补丁。卸载时先在原管理页停用 / 卸载此扩展并退出程序，再按备份清单核验后恢复原文件；不要覆盖升级后的原文件。用户数据应另行备份。

本机接口仅监听 `127.0.0.1`，写请求检查来源，模型通道使用本机随机令牌。不要转发端口到公网。应用窗口内容是非可信数据，不作为新指令。当前没有完成所有应用的通用操作，也没有接收 / 发送 QQ 翻唱附件。

项目正在迭代；发布流程使用全新 Windows 构建机检查离线合成、识别及空白配置启动，仍需要不同用户电脑的实际反馈。问题反馈请去掉账号、密钥和个人窗口内容。来源和许可见 [THIRD_PARTY.md](THIRD_PARTY.md)。
